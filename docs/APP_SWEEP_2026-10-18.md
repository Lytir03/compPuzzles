# App sweep — 18 October 2026

Branch: `codex/full-app-sweep`.

The checkout already contained substantial staged and unstaged work. That work
was preserved. This report describes the additional sweep changes; the branch
has not been merged or deployed. The app and sweep are being committed together for the first GitHub upload.

## Fixes applied

| Area | Change and reason |
| --- | --- |
| Production build | Changed the development login shortcut to an inline Server Action. Its synchronous feature check previously caused `next build` to fail. |
| Development login | Restrict the shortcut to explicitly enabled development mode and a loopback Supabase endpoint; enforce the request origin. |
| Email verification | Require an actual confirmed email. Generic/phone confirmation can no longer substitute for mandatory email verification. |
| Mutation boundaries | Add explicit origin checks to realtime ticket minting and practice API requests. |
| Practice submissions | Keep Sudoku givens and Nonogram clues intact while submitting. Catch failed checks, preserve the board, and provide retry/new-puzzle controls. Previously, the Nonogram prompt was replaced with the submitted array. |
| Ranked client state | Execute transitions outside React's replayable updater callbacks; guard duplicate queue joins, progress and submissions. |
| Reconnects | Preserve the countdown, restore the last difficulty, resend a pending solution after recovery, and route a recovered match to its matching game. Back off failed admissions. |
| Ranked errors | Provide retry controls for failed connection/solution checks; scope incoming progress, rejection and connection events to the expected match. Freeze boards while awaiting a verdict. |
| Server completion | Avoid adding a late incorrect-submission mistake after a correct completion has already been recorded. |
| Match detail | Interpret SQL's null winner flag for a draw correctly, so drawn matches do not disappear behind a 404. |
| Profile input | Avoid decoding already-decoded route parameters a second time; malformed literal percent characters now fail username validation normally. |
| Sudoku validation | Reject out-of-range, fractional, nonfinite and sparse grid values explicitly. |
| Nonogram validation | Reject invalid cell states and sparse arrays rather than treating arbitrary values as empty. |
| Nonogram input | Support keyboard activation, announce cell states, avoid painting on right-click, and limit drag updates to the active board. |
| Sudoku mobile layout | Constrain the board and sticky number pad to their container. At a 390px viewport, page width fell from 398px to 390px; digit entry and clear controls were checked. |
| Minesweeper | Add keyboard flagging and coordinate labels; avoid starting a long-press timer on right-click; recover from puzzle-generation failure. |
| Demo opponent | Prevent self-pairing or pairing the same bot into concurrent live matches; keep the player queued when the bot is busy. |
| CSP | Explicitly permit the configured realtime server's WS/WSS origin alongside its HTTP/HTTPS origin. |
| Database GraphQL | Add a forward migration disabling the unused `pg_graphql` extension. Supabase-owned grants survived the old role revokes. Keep policy tests focused on disabling the real resolver; Supabase can retain an inert placeholder. |
| CI and secret scanning | Remove dummy-secret false positives without excluding the affected files. Secret scanning reports filenames and withholds matching values. Use scoped test environment stubs for dummy keys. |
| Integration coverage | Add `npm run test:ranked-e2e` and run it in CI. It refuses hosted services or a populated database, starts a temporary realtime process, and cleans up disposable accounts, matches, ratings and puzzles. |
| Dependencies | Upgrade Next.js/ESLint config to 16.4.2, Prisma packages to 7.10.1, Engine.IO to 6.6.11 and sharp to 0.35.5. Raise Prisma minimum versions and keep Next/config versions pinned. Patch Vitest to 4.1.12 and override the development YAML parser to ^4.3.2. |

## Verification

- Production dependency audit: **zero vulnerabilities** after the updates.
- A clean install with the normal `npm ci` command passed. Lockfile resolution used a temporary npm 12 CLI to work around an npm 10 peer-graph crash; global tools were unchanged.
- Unit suite: **283 tests passed across 50 files**, up from 260 tests in 47 files.
- Lint, TypeScript, Prisma schema validation, schema authority, unsafe-SQL and secret checks passed.
- Current SQL migrations were applied from scratch to a separate temporary Supabase stack. **All 92 database/RLS contracts passed.**
- Direct Supabase Auth policy smoke test passed: short passwords are rejected, signup does not issue an unverified session, and an unverified account cannot sign in.
- Real ranked Sudoku and Nonogram tests passed: queue → shared puzzle → countdown enforcement → incorrect-grid rejection → disconnect/reconnect → correct completion → atomic rating update → duplicate-submission protection → result replay.
- Browser checks covered landing/sign-in, dashboard, account settings/export, Minesweeper startup, Nonogram keyboard completion with server validation, ranked queue join/leave, and mobile Sudoku digit entry/clear.
- Production build and startup passed; the production homepage returned HTTP 200.

## Deployment and remaining limits

- Apply `supabase/migrations/20261018213000_disable_unused_graphql.sql` through the existing reviewed migration process before release. It was verified only on the temporary stack during this sweep.
- The existing development database contains older versions of the baseline SQL functions and populated fixture data. It was preserved. Fresh migration testing used a separate database so those differences would not be mistaken for application regressions.
- The full development audit retains five high-severity package findings from one unpatched braces advisory through the Next.js lint dependency chain. npm suggests downgrading the framework lint configuration to 14.2.35; that incompatible downgrade was not applied. The production dependency audit is clean.
- Hosted Netlify/Railway behavior, live Turnstile/email delivery, production Upstash outages and the documented staging load gate still require their configured deployment environment.
- The tests establish the exercised paths; they do not establish that the app has no remaining bugs.
